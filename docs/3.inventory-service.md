# Inventory Service

Service quản lý tồn kho - đảm nhiệm việc check stock và trừ hàng khi có đơn.

## Thông Tin Cơ Bản

- **Port**: 8082
- **Swagger**: [http://localhost:8082/swagger-ui.html](http://localhost:8082/swagger-ui.html)
- **Database**: PostgreSQL (port 25432)

## Chức Năng

Service này làm 2 việc:

- Check stock levels cho các products
- Trừ stock khi Order Service tạo đơn thành công

## API

### POST /api/inventories/stocks-by-product-codes

Check stock cho nhiều products cùng lúc.

**Request**:

```json
{
  "productCodes": ["P001", "P002"]
}
```

**Response**:

```json
{
  "data": [
    { "productCode": "P001", "quantity": 50 },
    { "productCode": "P002", "quantity": 30 }
  ]
}
```

### POST /api/inventories/deduct

Trừ stock (được Order Service gọi).

**Request**:

```json
{
  "items": [{ "productCode": "P001", "quantity": 2 }],
  "orderCode": "ORD-123"
}
```

**Response**: Success hoặc error nếu không đủ stock.

## Database

Service dùng 2 bảng:

**1. inventory** - Số lượng tồn kho

```sql
CREATE TABLE inventory (
    product_code VARCHAR PRIMARY KEY,
    quantity     INTEGER NOT NULL CHECK (quantity >= 0)
);
```

**2. inventory_history** - Lịch sử thay đổi

```sql
CREATE TABLE inventory_history (
    product_code    VARCHAR NOT NULL,
    change_quantity INTEGER NOT NULL,  -- Số lượng thay đổi (âm = trừ)
    reason          VARCHAR,           -- ORDER_CREATED, RESTOCKED...
    reference_id    VARCHAR,           -- Order code
    created_at      TIMESTAMP
);
```

## Business Logic

### Pessimistic Locking

Service dùng `SELECT FOR UPDATE` để lock records trong transaction:

```java
@Query("SELECT i FROM Inventory i WHERE i.productCode IN :codes FOR UPDATE")
List<Inventory> findAndLock(@Param("codes") List<String> codes);
```

**Tại sao cần lock?** Tránh 2 orders cùng lúc trừ stock → data inconsistency.

### Sorted Product Codes

Trước khi lock, service sort product codes theo alphabet:

```java
List<String> sorted = productCodes.stream()
    .sorted()
    .collect(Collectors.toList());
```

**Tại sao sort?** Tránh deadlock khi 2 transactions lock theo thứ tự khác nhau.

**Ví dụ**:

```
Transaction 1: Lock [P001, P002]
Transaction 2: Lock [P002, P001]  ← Deadlock!

Sau khi sort:
Transaction 1: Lock [P001, P002]
Transaction 2: Lock [P001, P002]  ← OK, chờ nhau
```

### Validation

Service validate 2 điều:

1. Tất cả products phải tồn tại
2. Đủ stock để trừ

Nếu fail → Throw exception, transaction rollback.

## Integration

### Với Order Service

Order Service gọi `/deduct` sau khi validate sản phẩm:

```
1. User tạo order
2. Order Service validate sản phẩm (Catalog)
3. Order Service deduct stock (Inventory) ← Đây
4. Nếu thành công → Lưu order
5. Nếu fail → Return lỗi cho user
```

### Với API Gateway

Gateway route `/inventory/**` đến service này.


## Testing

Service test với Testcontainers + PostgreSQL:

```java
@Test
void shouldDeductStock() {
    // Given: Product có 10 trong kho
    // When: Trừ 5
    inventoryService.deduct(items, "ORD-123");
    // Then: Còn 5
    assertEquals(5, inventory.getQuantity());
}
```

Test cả concurrency (nhiều threads cùng trừ) để verify locking works.


## Troubleshooting

**Deadlock detected**:

- Kiểm tra có sort product codes chưa
- Check logs có errrors from PostgreSQL

**Stock không đủ**:

- Normal behavior - trả lỗi cho Order Service
- Order Service sẽ báo user

**Connection timeout**:

- DB có đang chạy không: `docker ps | grep inventory-db`
- Check port 25432
