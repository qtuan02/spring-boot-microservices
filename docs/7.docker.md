# Docker Workflow

Hướng dẫn dùng Docker để build, run và quản lý services. Dự án dùng **Spring Boot Buildpacks** - không cần viết Dockerfile.

## Tại Sao Dùng Docker?

- ✅ **Consistency** - Môi trường giống nhau ở dev/staging/production
- ✅ **Isolation** - Mỗi service chạy riêng trong container
- ✅ **Portability** - "Works on my machine" → "Works everywhere"
- ✅ **Easy Setup** - Không cần cài Java/Maven trên máy
- ✅ **Resource Control** - Giới hạn CPU/Memory per service

## Docker Files

```
deployment/docker-compose/
├── infra.yml      # Infrastructure (DB, RabbitMQ, MailHog)
└── apps.yml       # Application services
```

## Quick Commands

**Chạy toàn bộ**:

```bash
task build  # Build images
task start  # Start tất cả
task stop   # Stop
```

**Chỉ infrastructure** (khi đang dev):

```bash
task start_infra    # Start DB + RabbitMQ
task stop_infra     # Stop
```

## Spring Boot Buildpacks

### Không Cần Dockerfile

Buildpacks tự động tạo Docker image:

```xml
<!-- pom.xml -->
<plugin>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-maven-plugin</artifactId>
    <configuration>
        <image>
            <name>qtuan02/ecommerce-${project.artifactId}</name>
        </image>
    </configuration>
</plugin>
```

**Build**:

```bash
./mvnw spring-boot:build-image -DskipTests
```

Tạo image `qtuan02/ecommerce-catalog-service`.

### Lợi Ích

**Dockerfile thường**:

- Phải viết thủ công
- Hard-code Java version
- Cần update khi có security patches
- Image size lớn

**Buildpacks**:

- Tự động detect và build
- Auto-chọn runtime phù hợp
- Auto-update base images
- Optimized layering → rebuild nhanh

**Image structure**:

```
├── OS base (Ubuntu)
├── Java runtime (JDK 21)
├── Dependencies (.jar)
└── Application code
```

Layer caching: Chỉ rebuild layer thay đổi.

## Docker Compose

### infra.yml - Infrastructure

**Chứa**:

- PostgreSQL (4 databases: catalog, inventory, order, notification)
- RabbitMQ
- MailHog

**Example**:

```yaml
services:
  catalog-db:
    image: postgres:18-alpine
    ports:
      - "15432:5432"
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
    healthcheck:
      test: ["CMD", "pg_isready", "-U", "postgres"]
      interval: 10s
    deploy:
      resources:
        limits:
          memory: 500m
```

### apps.yml - Applications

**Chứa**: Tất cả microservices

**Example**:

```yaml
services:
  catalog-service:
    image: qtuan02/ecommerce-catalog-service
    ports:
      - "8081:8081"
    environment:
      DB_URL: jdbc:postgresql://catalog-db:5432/postgres
      DB_USERNAME: postgres
      DB_PASSWORD: postgres
    depends_on:
      catalog-db:
        condition: service_healthy
    deploy:
      resources:
        limits:
          memory: 700m
```

**Key points**:

- `depends_on` với `condition: service_healthy` → Đợi DB ready
- Environment variables override configs
- `restart: unless-stopped` → Auto restart khi crash
- Memory limits → Tránh OOM

## Docker Networks

Containers trong cùng network gọi nhau bằng tên:

```bash
# Inside order-service container
curl http://catalog-service:8081/api/products  # ✅ Works (container name)
curl http://localhost:8081/api/products        # ❌ Fails
```

## Environment Variables

**Local**:

```properties
spring.datasource.url=jdbc:postgresql://localhost:15432/postgres
```

**Docker**:

```yaml
environment:
  DB_URL: jdbc:postgresql://catalog-db:5432/postgres
```

**Mapping**:

- Local: `localhost:15432` → Host machine
- Docker: `catalog-db:5432` → Container name

## Logs

```bash

docker compose -f deployment/docker-compose/apps.yml logs

docker compose -f deployment/docker-compose/apps.yml logs -f

```

## Debugging

**Exec vào container**:

```bash
docker exec -it catalog-service bash

# PostgreSQL
docker exec -it catalog-db psql -U postgres

# Check env vars
docker exec catalog-service env
```

**Check ports**:

```bash
docker ps

# PORTS column:
# 0.0.0.0:8081->8081/tcp   ← Exposed
# 8081/tcp                  ← Not exposed
```

**Network debugging**:

```bash
docker exec -it order-service ping catalog-service
```

## Workflows

**Development**:

```bash
# 1. Start infra
task start_infra

# 2. Run services bằng IDE/Maven
cd catalog-service && ./mvnw spring-boot:run
```

**Full Docker**:

```bash
# 1. Code changes
# 2. Rebuild
task build

# 3. Restart service
docker compose -f deployment/docker-compose/apps.yml up -d catalog-service

# Or restart all
task restart
```

## Troubleshooting

**Container không start**:

```bash
docker logs catalog-service

# Common issues:
# - Port already used
# - Database not healthy
# - Missing env vars
```

**DB connection failed**:

```bash
# Check DB running
docker ps | grep catalog-db

# Check health
docker inspect catalog-db | grep Health -A 10
```

**Out of memory**:

```bash
docker stats  # Check usage

# Increase limit in apps.yml:
deploy:
  resources:
    limits:
      memory: 1g
```

**Clean up**:

```bash
# Stop all
docker compose -f deployment/docker-compose/infra.yml down
docker compose -f deployment/docker-compose/apps.yml down

# Remove volumes (DATA LOSS!)
docker compose -f deployment/docker-compose/infra.yml down -v

# Clean images
docker system prune -a
```

## Production Tips

**1. Secrets** - Dùng Docker secrets, không hardcode passwords:

```yaml
environment:
  DB_PASSWORD_FILE: /run/secrets/db_password
secrets:
  - db_password
```

**2. Image tags** - Dùng specific version:

```yaml
# ❌ Bad
image: qtuan02/ecommerce-catalog:latest

# ✅ Good
image: qtuan02/ecommerce-catalog:1.2.3
```

**3. Logging**:

```yaml
logging:
  driver: "json-file"
  options:
    max-size: "10m"
    max-file: "3"
```
