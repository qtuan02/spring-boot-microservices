# Order Service

Service xử lý đơn hàng - service phức tạp nhất với nhiều integrations và patterns.

## Thông Tin Cơ Bản

- **Port**: 8083
- **Swagger**: [http://localhost:8083/swagger-ui.html](http://localhost:8083/swagger-ui.html)
- **Database**: PostgreSQL (port 35432)
- **Message Broker**: RabbitMQ

## Chức Năng

Service này làm 5 việc chính:

- Tạo đơn hàng (validate products + inventory)
- Deduct stock từ Inventory Service
- Publish events sang RabbitMQ (Transactional Outbox pattern)
- Process đơn hàng bất đồng bộ (scheduled job)
- Query đơn hàng của user

## API

### POST /api/orders

Tạo đơn hàng mới.

**Request**:

```json
{
  "customer": {
    "name": "Nguyen Van A",
    "email": "test@example.com",
    "phone": "0123456789"
  },
  "deliveryAddress": {
    "addressLine1": "123 Main St",

    "country": "VIETNAM"
  },
  "items": [
    { "code": "P001", "name": "Product", "price": 29.99, "quantity": 2 }
  ]

```

**Response**: `{"orderNumber": "550e8400..."}`

Có thể fail nếu:

- Sản phẩm không tồn tại
- Giá không đúng
- Không đủ stock

### GET /api/orders

Lấy danh sách đơn hàng của user.

### GET /api/orders/{orderNumber}

Xem chi tiết 1 đơn.

## Database

Service dùng 4 bảng:

**1. orders** - Thông tin đơn hàng

```sql
CREATE TABLE orders (
    order_number    VARCHAR PRIMARY KEY,
    user_name       VARCHAR NOT NULL,
    customer_name   VARCHAR NOT NULL,
    customer_email  VARCHAR NOT NULL,
    delivery_address JSONB,         -- Địa chỉ dạng JSON
    status          VARCHAR NOT NULL -- NEW, DELIVERED, CANCELLED...
);
```

**Order statuses**:

- `NEW` - Đơn mới tạo
- `IN_PROCESS` - Đang xử lý
- `DELIVERED` - Đã giao
- `CANCELLED` - Đã hủy
- `ERROR` - Có lỗi

**2. order_items** - Items trong đơn

```sql
CREATE TABLE order_items (
    code      VARCHAR,
    name      VARCHAR,
    price     NUMERIC,
    quantity  INTEGER,
    order_id  BIGINT REFERENCES orders(id)
);
```

**3. order_events** - Transactional Outbox

```sql
CREATE TABLE order_events (
    order_number VARCHAR,
    event_type   VARCHAR,  -- OrderCreated, OrderDelivered...
    payload      JSONB,
    created_at   TIMESTAMP
);
```

**4. shedlock** - Distributed locking cho scheduled jobs

## Event-Driven Architecture

### Transactional Outbox Pattern

Service dùng pattern này để đảm bảo events không bị mất:

**Flow**:

```
1. User tạo order
2. Trong 1 transaction:
   - Lưu Order vào DB
   - Lưu OrderCreatedEvent vào order_events
3. Transaction commit
4. Job (chạy mỗi 5s) đọc order_events và publish lên RabbitMQ
5. Xóa event sau khi publish thành công
```

**Tại sao cần?** Nếu RabbitMQ down lúc tạo order, event không mất vì đã lưu DB.

### RabbitMQ Events

**Exchange**: `orders-exchange`

**Queues**:

- `new-orders` - Đơn mới tạo
- `delivered-orders` - Đơn đã giao
- `cancelled-orders` - Đơn bị hủy
- `error-orders` - Đơn lỗi

**Event example**:

```json
{
  "orderNumber": "550e8400...",
  "customerName": "Nguyen Van A",
  "customerEmail": "test@example.com",
  "items": [...]
}
```

## Scheduled Jobs

Service có 2 jobs chạy background:

**1. OrderEventPublishingJob** (mỗi 5 giây)

- Đọc bảng `order_events`
- Publish lên RabbitMQ
- Xóa sau khi thành công

**2. OrderProcessingJob** (mỗi 10 giây)

- Lấy orders có status=NEW
- Check có thể giao đến country này không
- Update status → DELIVERED hoặc CANCELLED

**Allowed countries**: VIETNAM, INDIA, USA, GERMANY

**ShedLock**: Đảm bảo chỉ 1 instance chạy job (distributed lock).

## Resilience Patterns

### Circuit Breaker

Áp dụng khi gọi Catalog/Inventory services:

**Config**:

- Mở circuit nếu >50% requests fail
- Đợi 10s trước khi thử lại
- Đếm 10 requests gần nhất

**States**:

- `CLOSED` - Normal, cho phép requests
- `OPEN` - Circuit mở, reject tất cả (fail fast)
- `HALF_OPEN` - Thử vài requests để test

### Retry Policy

Tự động retry khi call fail:

- Tối đa 3 lần (1 lần đầu + 2 retries)
- Đợi 500ms giữa các lần

## Order Creation Flow

```
1. User tạo order
2. Validate products (Catalog Service)
3. Deduct stock (Inventory Service)
4. Save order + event (1 transaction)
5. Return order number
6. Job publish event → RabbitMQ
7. Notification Service nhận event → Gửi email
```

## Integration

**Catalog Service**: Validate sản phẩm tồn tại và giá đúng

**Inventory Service**: Trừ stock

**Notification Service**: Nhận events từ RabbitMQ

## Troubleshooting

**Events không publish**:

- Check OrderEventPublishingJob có chạy không (xem logs)
- Verify RabbitMQ connection: `docker logs ecommerce-rabbitmq`
- Check bảng `order_events` có records không

**Circuit breaker mở liên tục**:

- Catalog/Inventory service có chạy không?
- Check metrics: `http://localhost:8083/actuator/circuitbreakers`

**ShedLock exception**:

- Bảng `shedlock` đã có chưa (Flyway migration)
- Nếu nhiều instances → chỉ 1 instance được lock (bình thường)
