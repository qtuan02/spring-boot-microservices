## 2. Monorepo Structure

Cấu trúc tổng quan của toàn bộ Repository:

```text
spring-boot-microservices/
├── .github/workflows/        # CI/CD Pipelines (GitHub Actions)
│   ├── catalog-service.yml
│   └── order-service.yml
├── deployment/               # Deployment Configurations
│   └── docker-compose/
│       ├── infra.yml         # Hạ tầng: DBs, Message Broker
│       └── apps.yml          # Services: Catalog, Order...
├── docs/                     # Documentation (Tài liệu dự án)
├── catalog-service/          # Source code Catalog Service
├── order-service/            # Source code Order Service
├── notification-service/     # Source code Notification Service
├── template-service/         # Source code Template Service
├── pom.xml                   # Parent POM (Quản lý versions chung)
├── Taskfile.yml              # Task Runner (Shortcuts lệnh)
├── .sdkmanrc                 # Cấu hình version Java/Maven (Mac/Linux)
├── .gitignore                # Git ignore config
└── README.md                 # Entry point documentation
```

## 3. Microservice Structure

Mỗi service được tổ chức theo **Layered Architecture** (Kiến trúc phân lớp), lấy cảm hứng từ **Hexagonal Architecture**.

### Tại sao lại chọn kiến trúc này?

Chúng ta chia code thành 3 lớp chính để đảm bảo sự tách biệt trách nhiệm:

**1. Web Layer (Adapter Inbound):**

- Chỉ chịu trách nhiệm giao tiếp với thế giới bên ngoài (REST API).
- Nhận request, validate dữ liệu đầu vào.
- **Không chứa logic nghiệp vụ**.

**2. Domain Layer (Core):**

- Trái tim của ứng dụng.
- Chứa Entity (Dữ liệu) và Service (Logic nghiệp vụ).
- **Không phụ thuộc vào Web hay các framework bên ngoài**.

**3. Infrastructure/Config Layer:**

- Chứa các cấu hình kết nối database, RabbitMQ, Swagger.
- Là nơi "gắn kết" các thành phần lại với nhau.

### Cấu trúc chi tiết

Dưới đây là cây thư mục chuẩn của một service (ví dụ `order-service`):

```text
[service-name]/
├── src/main/java/com/qtuan02/[service]/
│   ├── Application.java           # [MAIN] Điểm khởi chạy ứng dụng Spring Boot
│   │
│   ├── web/                       # [WEB LAYER] Xử lý Request/Response
│   │   ├── controllers/           # REST Controllers (API Endpoints)
│   │   ├── models/                # DTOs (Data Transfer Objects) - Request/Response bodies
│   │   └── exceptions/            # Global Exception Handler (Xử lý lỗi tập trung)
│   │
│   ├── domain/                    # [DOMAIN LAYER] Logic nghiệp vụ cốt lõi
│   │   ├── models/                # Value Objects, Enums, Internal Models
│   │   │   ├── *Status.java       # Enums (e.g. OrderStatus)
│   │   │   └── *VO.java           # Value Objects (e.g. Address)
│   │   ├── *Entity.java           # JPA Entities (Ánh xạ bảng Database)
│   │   ├── *Repository.java       # Interfaces giao tiếp Database (Spring Data JPA)
│   │   ├── *Service.java          # Service chứa Business Logic chính
│   │   └── *Mapper.java           # Chuyển đổi dữ liệu giữa Entity <-> DTO
│   │
│   ├── config/                    # [CONFIG] Cấu hình hệ thống
│   │   ├── SwaggerConfig.java     # Cấu hình OpenAPI/Swagger UI
│   │   ├── RabbitMQConfig.java    # Cấu hình Queue, Exchange (nếu có dùng RabbitMQ)
│   │   └── RestClientConfig.java  # Cấu hình RestTemplate/WebClient
│   │
│   ├── clients/                   # [CLIENTS] Gọi External Services
│   │   └── *Client.java           # Feign Client hoặc HTTP Client gọi service khác
│   │
│   └── jobs/                      # [JOBS] Các tác vụ chạy ngầm (nếu có)
│       └── *Job.java              # Scheduled Tasks (ShedLock)
│
└── src/main/resources/
    ├── application.properties     # File cấu hình chính (DB url, server port...)
    └── db/migration/              # [FLYWAY] Quản lý version Database
        ├── V1__create_tables.sql  # Script tạo bảng
        └── V2__insert_data.sql    # Script thêm dữ liệu mẫu
```
